# 73: The hero's «استكشف المنصة ↓» button takes the visitor to the four units

**What to build:** On the home page, the hero's second button, «استكشف المنصة ↓» ("Explore the platform ↓" on the English home page), scrolls the page down to the four-units section: the one headed «أربع وحدات. سجل واحد يجمعها.» with the Screen mocks. ## Agent Brief

**Category:** bug (inherited from the Reference site; the founder calls the fix an enhancement)
**Summary:** Point the home hero's second button at the four-units section instead of an address nothing on the page carries, land it clear of the fixed header, and hide the button when that section is switched off.

**Current behaviour (confirmed 23 September 2026):**

- The home hero's second button links to `#journey`. No section on the home page carries that address. The Reference site's home page has the same dead link. The rebuild copied it knowingly: a comment beside the link says it goes nowhere.
- On the Product page, the same button links to `#journey` and works, because the Product page's journey section carries that address.
- The four-units section's address is `#jt`. It has no allowance for the fixed header, unlike the site's other jump targets (the demo form, the tool page's sections, the start page's questions), which stop 78px down.
- Each home section can be switched off in the CMS. The four units are one of them.
- Where each hero button lands is decided in code, not in the CMS: an Editor changes what a button says, never where it goes. Keep it that way.

**Desired behaviour (decided by the founder, 23 September 2026):**

- The button lands on the four-units section of the same page, not on the Product page's journey. The founder chose this because the "↓" in the label promises a scroll, not a new page.
- Arabic and English home pages both.
- Switched off, the section takes the button with it (option A). The founder turned down leaving a dead button and pointing it at whichever section is next.
- **Wording:** as with ticket 72, call this an enhancement over the Reference site, not "a deliberate divergence". It still has to be written in the code, so a later session does not put `#journey` back to match `reference/`.

**Tests to expect to change:** the Reference comparisons that measure the hero compare where its buttons sit, not where they point, so they should be unaffected while the section is on. A test that reads the hero's links, if one does, will see the new address. No ADR is needed: the change is easy to reverse and its reason is plain.
