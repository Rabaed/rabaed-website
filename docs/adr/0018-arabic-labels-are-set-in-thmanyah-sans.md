# Arabic labels are set in Thmanyah Sans, untracked

The small orange label over nearly every section's heading — the eyebrow — is set in DM Mono on the Reference site, and so are the labels that share its voice: the closing section's steps, the step cards' «01 · إعداد», «المخرَج» on the four units and the journey. DM Mono has no Arabic glyphs, so on every one of the Reference site's nine pages what a visitor read was the browser's last-resort monospace, its joined letters pulled apart by the rule's `.12em` tracking. The spec forbids exactly that (spec: Design system), and bug 45 asked the founder what the labels should look like instead, since the answer changes every page.

The founder chose **Thmanyah Sans**, on 23 September 2026, over the three options the bug offered, which all kept the site's body face. So every Arabic label is set in Thmanyah Sans at the Reference site's size and colour, **in Regular, with no tracking**: spacing Arabic letters out breaks the joins between them in any face. Regular even where the Reference site's label is bold — the closing section's steps and the path's stages, and «ما يعبر رسمياً» — because each weight is its own 76 KB file (below), and the founder chose one file over a bolder step label. `--label-face` in `tokens.css` names the face, with the page's own Arabic stack behind it for the moment before it arrives, and each label's rule has an Arabic-only override beside it — `:where([dir="rtl"])`, so the override adds nothing to the rule's weight and wins only by coming after it. **English pages keep DM Mono and its tracking**: for Latin it is the right face, and the defect was never theirs.

Numerals inside a label stay in DM Mono where the markup already says so (`.mono`, as in «01 · إعداد»); only the Arabic changed.

## The licence

Thmanyah Sans is not an open font. It is thmanyah Publishing and Distribution's, under their own licence (`assets/thmanyah/LICENSE.pdf`; the Arabic text governs). It permits commercial use in websites, and forbids redistributing the files — uploading or hosting them anywhere they can be downloaded — and making them available to others as font files, "including through web embedding". A web font is downloaded by every visitor's browser, so the licence as written does not plainly cover this site.

The founder obtained the files from thmanyah directly and settled this with them: rabaed may use the face on its site as long as it is credited as thmanyah's and not presented as rabaed's own. The files are therefore served **exactly as thmanyah ships them, under their own names** (`thmanyahsans-Regular.woff2`), unsubset and unmodified, as the family `Thmanyah Sans`, so anyone who inspects the page sees whose face it is.

**The repository is public, and that is covered only for now.** Committing the files to a public repository is itself hosting them where they can be downloaded. The founder raised this with thmanyah, who agreed it may stay public for the moment on condition that it is made private **within three months — by 23 December 2026**. The founder intends to do it within a couple of weeks.

## Consequences

- **The repository must be made private by 23 December 2026.** Until then the font files sit in a public repository by thmanyah's agreement, not by the licence's terms. If that date passes, the files have to come out of the repository and its history.
- **The arrangement with thmanyah is not yet in writing.** The licence says an exception is effective only if it is made in writing and issued by thmanyah. A confirming email from them is the thing to keep with this record.
- **No other file from the thmanyah folder may be added without the same check** — the Serif faces included. The permission covers what the founder agreed with thmanyah, not the family.
- **The files live in `assets/thmanyah/`, not `assets/fonts/`,** because `npm run fonts:sync` empties `assets/fonts/` and writes it again from `@fontsource`.
- **76 KB more on every Arabic page.** Thmanyah's files are whole — about 76 KB each, against 45 KB for an IBM Plex Sans Arabic face split to its Arabic letters — because the licence forbids cutting a file down, which rules out the subsetting every other face on the site has. So the site serves one weight, Regular. A bold label would cost a second 76 KB on every page that has one; `fonts.spec.ts` fails on any Arabic label that asks Thmanyah for more than 400, since the browser would fake a bold rather than fetch one. `performance.spec.ts` raises each Arabic page's budget by 80 KB, and the English pages, which never fetch the face, keep theirs. The face swaps in when it lands, and the labels do not move when it does: see the next point.
- **Its line box is IBM Plex Sans Arabic's.** Thmanyah reserves less room above and below its baseline than IBM Plex does, and where a line mixes it with DM Mono — a label and its numeral — or sets it in a pill on a line of body text, that made the line 1px to 4px taller or shorter than the Reference site's. `ascent-override: 108.5%` and `descent-override: 41.5%`, IBM Plex's own measured figures, give it IBM Plex's line box. No glyph changes and the file is untouched.
- **The comparisons with the Reference site read the label face as DM Mono.** `tests/e2e/geometry.ts` maps the face back to what the Reference site declares, as it already maps ADR-0011's colours and strips ADR-0012's stand-in, so every comparison still holds the label's size, weight, line height and place — and a Thmanyah face turning up anywhere the Reference site set IBM Plex Sans Arabic still fails. The step and stage labels, Regular where the Reference site's are bold, leave their typeface out and keep the rest.
- **Held by `tests/e2e/fonts.spec.ts`,** which walks every Arabic page at a phone's width and a desktop's and fails on any Arabic text set in a face without Arabic glyphs, or tracked out as a label is; and checks that the face actually loads. The Reference site's headings are drawn in by .01em to .02em and a few phrases let out by as much. That is too little to part a join, it is the design's, and it is left as it is.
